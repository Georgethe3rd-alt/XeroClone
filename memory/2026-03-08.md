## Ollama Integration Strategy Discussion (09:17)

**Wayne's Goal**: Use Ollama for simple tasks (heartbeats, routine checks) to avoid burning Anthropic/OpenAI tokens

**The Risk**: Last attempt broke OpenClaw by changing the default model system-wide

**Safe Architecture Proposed**:
1. **Keep George on Claude** - Main session stays on anthropic/claude-opus-4-6 (don't touch)
2. **Spawn separate worker on Ollama** - Create dedicated heartbeat-agent using Ollama llama3.2:1b
3. **Explicit model per task** - Use sessions_spawn with model parameter (never change defaults)
4. **Worker reports to George** - Heartbeat agent does simple checks, reports findings back to main session

**Pattern**:
- Main brain (George): Claude for complex reasoning, orchestration
- Heartbeat worker: Ollama for routine checks (email scan, calendar, notifications)
- Clear separation: different sessions, explicit models, no global changes

**Why It's Safe**:
- George's model stays untouched
- Ollama agent is isolated (sessions_spawn)
- If Ollama agent fails, doesn't affect George
- Explicit model specification per spawn (not system default)

**Lesson from Past Failure**: 
- Changing default model = breaks core functionality
- Solution: Never touch defaults, always specify explicitly per session

**Status**: Proposed architecture, awaiting approval to build proof of concept
